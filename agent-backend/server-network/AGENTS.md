# server-network 工程约束

本目录承载 Spring Boot 组合根、HTTP 协议适配和单机业务数据的 SQLite 持久化。除根目录 `AGENTS.md` 外，修改本模块还必须遵守以下规则。

## Agent 业务工具

- 日历、财务、资料和学习等业务 Agent Tool Adapter 归属本模块，通过对应领域 Service 复用业务规则；不得调用 Controller、绕过 Service 直接访问 Repository，或在 Tool 中复制领域校验。
- `server-agents` 只提供 Tool 注册 seam 与通用执行契约；业务 Tool 通过该 seam 自动注册，禁止为注册业务 Tool 建立 `server-agents` 到 `server-network` 的反向依赖。
- Tool 不接受调用方传入的 `ownerId`，必须通过 `CurrentUserProvider` 获取当前用户；读取 Tool 才能加入安全白名单，任何业务写入在非完全访问模式下都必须进入统一确认流程。
- 业务写 Tool 使用 `agent_tool_operation` 保存按用户、Tool 名称和幂等键隔离的执行结果，并与领域写入处于同一事务；该表只用于防止重复执行，不得成为业务事实来源。

## 本地数据库

- 业务数据库固定存放于 `~/.butvan-agent/data/butvan.db`；测试必须覆盖路径并使用临时目录，禁止触碰用户真实数据。
- 数据库结构只允许通过 `src/main/resources/db/migration/` 下的 Flyway 迁移演进；已发布迁移不得修改，只能新增更高版本迁移。
- SQLite 数据源统一由 `config/database/` 创建，必须启用外键、WAL 与锁等待；前端、Tauri 和其他进程不得绕过后端直接写库。
- 金额按最小货币单位整数存储；日期、时间、时区分别表达；日志不得输出手记正文、完整财务内容或其他敏感业务数据。
- 数据表按业务域归属。跨域读取必须经过领域 Service，禁止 Controller 或其他模块直接拼接 SQL 查询别的领域表。

## 日记录

- `daily_event` 只保存所有日记录共有字段；待办、日程、花销、手记及未来学习记录等类型使用独立详情表。
- 可检索、筛选、统计或参与约束的字段必须建正式列；`extension_json` 仅保存低频、未稳定的扩展信息，禁止替代正式业务模型。
- 新增日记录类型必须提供类型处理器、详情迁移、类型化请求 DTO、前端降级展示和公开接口测试，不得修改已有类型详情表来塞入无关字段。
- 核心记录与详情必须在同一事务内写入；修改和删除必须检查所有者，覆盖写入使用版本号避免静默丢失更新。
- 待办支持不重复、每日、每周、每月四种周期；每周待办必须保存 ISO 星期（1 表示周一、7 表示周日），每月待办必须保存日期（1 至 31），只在从生效日起匹配规则的日期展示。周期待办按自然日、周一开始的自然周或自然月分别记录完成状态。
- 月历摘要不得把周期待办提前投影到未来日期，待办完成率只统计截至今日已生效的待办；当日详情按一次性、每日、每周、每月的顺序展示。
- 日程开始时间与结束时间均为可选；仅在两者同时存在时校验结束时间晚于开始时间，前端不得用虚构默认时间替代未知时间。

## 财务记录

- `finance/` 独立承载资产账户、收入、支出与收益计提；日历不直接修改财务表，但日历摘要与按日详情必须通过只读收支分析 Service 合并历史花销、财务支出和财务收入。
- 每条手工收支必须关联一个归属当前用户的资产账户，并在同一事务内写入流水、调整余额；支出不得造成负余额。
- 新建账户分类统一使用微信余额、微信零钱通、支付宝余额、支付宝余额宝、银行卡与其他；已保存的 `wechat`、`alipay`、`cash` 旧类型继续只读兼容。
- 生息账户以用户填写的当前年化率按 365 天逐日复利估算，查询财务总览或新增流水前补齐至当日；自动收益使用唯一日流水防止重复入账，并计入收入统计。
- 财务金额继续按最小货币单位整数保存；收益率使用独立正式列，自动流水必须保留可识别的 `source`。
- 财务月支出、日历月支出和支出图表必须复用同一跨域只读投影；图表接口提供连续日期、每日支出总额、支出分类金额与每日收入总额，避免前端分别计算形成口径漂移。
- 财务“最近流水”需按时间合并财务流水与旧日历花销；旧日历花销只做兼容展示，不得反向绑定或修改资产账户余额。
- 财务首页总览仅承担最近流水；完整历史由 `GET /agent/finance/transactions` 按需读取，响应沿用 `TransactionResponse` 列表并包含账户、分类、来源、日期与时间。
- 收入与支出分类分别维护内置选项和用户使用过的自定义选项；成功创建流水时自动记住分类，两个类型之间不得混用自定义分类。

## 学习记录

- `study/` 独立承载学习时段的开始、结束、补卡、修改、删除与时长统计；学习时段同时作为 `study` 类型日记录写入 `daily_event`，专属字段保存在 `study_session_detail`。
- 同一用户最多存在一个进行中的学习时段；结束时间必须晚于开始时间，已结束时段不得相互重叠，所有写入必须在同一事务内维护公共记录与学习详情。
- 学习时长由后端根据时间点计算，前端不得提交或持久化计算后的时长；跨自然日时按学习时段记录的时区拆分到每天，保证日、周、月统计口径一致。
- 项目内开始、补卡及未来快捷指令都是学习模块的输入适配器，必须复用同一领域校验与统计接口；来源使用稳定枚举值，不得根据文案推断。
- 学习分类支持内置选项和用户自定义输入；开始、补卡或修改成功时自动记住分类，后续录入必须可再次选择。
- 学习状态通过用户级 SSE 实时同步：领域写入必须在事务提交后发布变更事件，订阅建连及自动重连时必须发送当前活动时段的权威快照；前端不得对活动学习接口进行定时轮询，断线期间遗漏的状态只通过重连快照恢复。

## 每日洞察

- `insight/` 只通过各领域公开 Service 组合日历、资料、财务与学习的只读统计，不得跨域拼接 SQL，也不得在查询时调用模型。
- 每日洞察以调用方提供的自然日和 IANA 时区为准；Slash Command 只负责触发和展示，不得在前端重复推导统计口径。

## Token 用量

- `token_usage_turn`、`token_usage_invocation` 与 `token_usage_tool` 是统计读模型；聊天 transcript 与系统用量 JSONL 是权威数据源，统计查询必须允许安全重建 SQLite 投影。
- 聊天轮次与非聊天调用分开建模；全局统计可以合并展示，但不得把会话标题等系统用途计入聊天轮次。
- 日期筛选使用应用所在时区的闭区间自然日；供应商未上报的实际用量保持不可用，不得通过字符数估算补齐。
- 输入分类与逐工具 Token 是本地估算投影，必须携带计数器版本并与供应商实际输入分开表达；个人画像与相关记忆必须独立归因，信封标签等包装开销继续归入 RAG Context；估算误差不得反向改写实际输入、输出或缓存 Token。

## 聊天上下文适配

- 稳定资料 ID 必须在 `chat/` 内校验所有权与可引用状态后再读取正文；前端不得自行展开资料正文，也不得提交可伪造的 RAG Token 归因。
- 画像辅助维护接口归属 `context/`，只允许操作 `CurrentUserProvider` 解析出的当前用户；检查接口只生成唯一待审核提案，确认接口必须校验画像 revision，拒绝接口不得修改当前画像。
- 用户可见命令与模型上下文分开传递，Transcript 只保存用户可见内容；实际送入模型的资料片段必须登记为 `RAG Context`。
- AI 分析命令只允许前端提交受控命令、范围、时区和逐次确认状态；业务数据必须由后端按当前用户读取、最小化后作为独立 `RAG Context` 注入。凡包含财务数据的命令都必须在每次请求中显式确认，不得持久化或复用同意状态。

## 资料库

- `record/` 独立承载按日期组织的个人资料库，内置随记、每日学习、每周复盘、读书心得和每日手记五种类型；产品界面统一称为“资料”，前端不得用自由字符串绕过类型约束。
- 资料标题可空，但标题与正文不得同时为空；富文本 HTML 用于编辑还原，纯文本列专用于搜索和摘要，标签使用正式关联表表达。
- Slash Command 资料引用选择器只分页读取未归档、未回收资料的轻量元数据，使用稳定资料 ID 传递引用，不得为候选列表加载完整正文或 HTML。
- 首页分类使用持久化 `record_tab`：系统 Tab 与用户自定义 Tab 共用同一模型，每条资料明确关联一个 Tab；“全部”仅是聚合视图，不是可写入分类。
- 每周复盘按 ISO 自然周（周一开始）绑定周年份和周序号；同一自然周允许保存多篇复盘，存在至少一篇即视为该周已复盘。
- 资料删除采用回收站软删除，用户主动清空后才永久删除；编辑、状态修改和恢复必须使用版本号避免静默覆盖。
- “每日手记”必须通过稳定 `source_reference` 在资料与日历之间双向同步：任一入口创建或编辑后另一入口立即可见；删除、回收与恢复动作必须同步维护对应投影，避免重复资料或孤儿数据。
- 附件文件保存于数据库同级的 `records/attachments/`，数据库只保存元数据；所有读写均须先校验资料所有者，单文件大小必须受限。
- 完整备份使用版本化 ZIP 格式，必须同时包含结构化恢复清单、人类可读 Markdown 和附件原文件；导入前先校验格式，并明确告知用户会替换当前资料库。

## 接口与测试

- Controller 只负责请求转换、当前用户解析与响应包装；领域规则必须位于 Service 或类型处理器。
- Agent 聊天流必须使用稳定 `runId`；`POST /agent/chat/runs/{runId}/cancel` 只做身份、session 与 DTO 适配，实际取消行为必须委托 `server-agents` 的活动运行注册表。该接口应幂等，响应的 `accepted` 只表示服务端已接管，前端只能以 SSE `cancelled` 或详情同步判定终态。
- 日历月视图只能读取轻量日期摘要；完整手记和类型详情按日加载。
- SQLite 集成测试必须通过公开 Service 或 HTTP 接口验证行为，不得把私有 SQL 实现作为测试契约。
