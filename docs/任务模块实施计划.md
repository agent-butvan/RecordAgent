# 任务模块实施计划

基线：main；开发分支：codex/task-module；独立工作区不修改日历分支。

已确认：首先支持 macOS；45 分钟连续使用、5 分钟空闲重置；系统通知与持续提醒窗口，手动确认后循环。

## 执行顺序

1. 建立任务配置、持久化、调度计算和真实 SQLite 集成测试。
2. 接入任务工作区、创建编辑、暂停恢复、预览、历史和 SSE。
3. 复用本地邮件配置，提供安全的设置、测试与任务投递。
4. 接入日报固定模板、独立渠道状态与恢复策略。
5. 接入 macOS 使用状态采集、原生通知、确认窗口与后台驻留。
6. 完成构建、类型检查、后端测试、DOX 复核并提交；不推送、不发布。

## 验证原则

测试仅使用临时数据库与模拟邮件投递，不读取用户真实配置或向外发信；不进行截图或手动界面检查。原生通知实际观感与系统权限流程在获准后单独验收。

## 当前交付状态

- 已实现任务 CRUD、启停、预览、手动执行、最近 50 条历史和 SSE 状态同步；支持一次、每日、每周、间隔与 macOS 久坐触发。
- 已实现桌面系统通知、提醒声音、待确认窗口与后台驻留；久坐按连续使用时长计时，空闲达到阈值、锁屏或采样中断即重置，确认后重新开始。
- 已实现日报固定模板的支出、待办、学习统计，支持桌面与邮件独立渠道；邮件可配置、绑定收件地址、发送测试邮件，并保留失败与结果未知时的人工重试入口。
- 已新增 SQLite 迁移、调度与日报单元测试，以及使用临时 SQLite 和模拟邮件服务的状态流转集成测试。macOS 原生通知的实际权限与窗口观感尚未在设备上人工验收。

## 约束与后续扩展

- 当前 main 尚未包含日历升级分支改动；其迁移使用 V17，本分支任务迁移使用 V18。集成或发布本分支前应先将日历 V17 合入 main，再合入任务分支；若已有数据库先运行 V18，再引入 V17，Flyway 默认迁移顺序会受阻。周期待办统计也需在集成时复核。
- 定时提醒与子 Agent 的 TaskDto 是不同领域，新增类型和接口使用 automation 前缀避免冲突。
- AI 总结、每周总结、对话创建、跨平台原生检测，以及安静时段、自动邮件重试和自定义邮件主题尚未实现，留待后续迭代。
