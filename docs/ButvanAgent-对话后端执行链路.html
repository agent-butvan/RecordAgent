前置

线程模型：一次对话 = 3 个虚拟线程协作

虚拟线程

① Controller 请求线程Tomcat 工作线程

接收 HTTP 请求 → 创建 SseEmitter 与 AgentStreamSession → 启动生产者 → 启动消费者 → 立即返回。不等待模型，不参与后续流式过程。

② 生产者虚拟线程AgentService.streamAgent 启动

执行 produceEvents(request, streamSession)：校验 → 落盘用户消息 → 调用 AgentScope agent.streamEvents(...) → 逐条 mapEvent → queue.put() 阻塞式投递 → 终态时写 assistant 消息。

③ 消费者虚拟线程Controller 内 sender

queue.take() 阻塞取事件 → emitter.send(...) 写 SSE → 遇终态事件（done / error）退出 → finally 中 session.cancel() + emitter.complete()。

解耦要点：生产者与消费者通过有界队列（容量 64）连接。队列满时生产者阻塞，客户端断开时 cancel() 置位 cancelled 并 interrupt 生产者，使其在下一个事件循环退出。

AgentController.streamChat：创建 SseEmitter 并组装双线程

HTTP 层
public SseEmitter streamChat(@RequestBody AgentUserCall request) { SseEmitter emitter = new SseEmitter(0L); // 0L = 超时由应用控制 AgentStreamSession session = agentService.streamAgent(request); // 立即返回 Thread sender = Thread.startVirtualThread(() -> { ... }); // 消费者 emitter.onCompletion(() -> { sender.interrupt(); session.cancel(); }); return emitter; }

传入 / 产出

对象值说明
入参 requestAgentUserCall(sessionId, context)原样传给 AgentService.streamAgent
SseEmitter emitternew SseEmitter(0L)0L 表示不启用 Spring 默认超时断开，由代码显式 complete() 关闭
sessionAgentStreamSession含有界队列（容量 64）、AtomicBoolean cancelled、生产者线程引用
返回值emitterSpring MVC 自动把 emitter 与 HTTP 响应绑定
消费者线程职责：while(!interrupted) → session.queue().take()（空队列阻塞等待）→ emitter.send(SseEmitter.event().name(eventName).data(payload)) → 若 event.isTerminal() 则 return。finally 统一 session.cancel() + emitter.complete()。onCompletion（浏览器断开）会 interrupt 消费者并再次 cancel 生产者。

AgentService.streamAgent：创建会话状态并启动生产者

业务层
public AgentStreamSession streamAgent(AgentUserCall request) { AgentStreamSession streamSession = new AgentStreamSession(); // 队列 64 + cancelled=false Thread producer = Thread.startVirtualThread(() -> produceEvents(request, streamSession)); streamSession.bindProducer(producer); return streamSession; }

AgentStreamSession 内部状态（传入值）

字段值用途
queueLinkedBlockingQueue<AgentStreamEvent>(64)生产者 put / 消费者 take 的缓冲，满 64 时生产者阻塞
cancelledAtomicBoolean(false)客户端断开后置 true，生产者据此提前退出
producerThread生产者虚拟线程引用cancel() 时 interrupt 使其从阻塞中唤醒
耗时：本方法只创建对象与线程，毫秒级返回。真正的模型调用全部发生在生产者虚拟线程内。

private void produceEvents(AgentUserCall request, AgentStreamSession streamSession) { StringBuilder assistantContent = new StringBuilder(); // 本轮正文累积器 Map<String, ToolExecutionDto> toolExecutions = new LinkedHashMap<>(); // 工具执行记录（保序） Instant startedAt = Instant.now(); // 耗时起点 if (!modelHolder.isInitialized()) { putEvent(streamSession, new AgentStreamEvent.Failed("请先完成模型配置。")); return; } sessionCatalogService.requireActive(request.sessionId()); // 会话归属 + ACTIVE 校验 String input = requireContent(request.context()); // 非空、≤20000 字符、strip }

三种结束方式

结束路径生产者行为落盘状态
正常完成AgentEvent 流结束 → finishAssistantMessage(COMPLETED) → putEvent(Completed) → 消费者发 done 后退出COMPLETED
模型/业务异常catch 异常 → 日志 → finishAssistantMessage(FAILED) → putEvent(Failed(msg)) → 消费者发 errorFAILED
客户端断开cancel() 置位 + interrupt → 生产者下一循环检查 isCancelled() → finishAssistantMessage(CANCELLED)CANCELLED
